## 핵심 키포인트
- **철학(부제 "당신의 레버리지를 위하여")**: 바이브코딩 기본기가 AX의 **레버리지(지렛대)**. 강사는 SI 구축 15년 경력.
- **구축 순서와 강 구성**: 문제정의→기획→디자인→개발→테스트. "앞=설계, 뒤=구현" 중 **1강=구현(개발자·디자이너 산출물)**, 2강=설계(기획자·PM)로 확장. "기능 많고 절차 복잡한 **혼자 쓰는** 시스템은 딸깍 — 공개 서비스는 그 이상."
- **시연: 정석몰(쇼핑몰) 구축** — **PRD 작성**부터 배포까지 단계별. 도구=코덱스/클로드 데스크톱, **마크다운(H1/H2/리스트)** = AI 바이브코딩의 표준 파일형식.
- **핵심 방법 — "하나씩 물어봐줘"(55개 기술 의사결정)**: *"나는 비개발자다. 의사결정에 필요한 기술요소 개념·선택옵션을 **한 번에 묻지 말고 하나씩 순차로** 물어봐줘."* → AI가 스택을 하나씩 설명, 사용자는 **개념·장단점·대체제·선택맥락**을 학습하며 **선택**. (예: Next.js 16, TypeScript, Vercel/Node, Tailwind CSS 4, Supabase(DB), Vitest(테스트), GA·구글태그[+개인정보 검토], MFA·비밀번호 정책, 외부 백업, PR 승인 후 프로덕션 배포 등)
- **구축·배포 실무**: 전체 구축(자율주행), 환경변수 파일 · `pnpm install`(package.json 의존성·node_modules) · PR→프리뷰→프로덕션 승격.

## 우리 업무 적용점
- **"한 번에 묻지 말고 하나씩"** = 비개발자가 기술 의사결정을 **이해하며** 내리는 학습법 = 우리 리뷰어2·검증 태도. [[no-fabrication-rule]]
- 스택 선택·PR 승인 배포 흐름 = 우리 프로젝트(ACS·KIS 등)의 구축/배포와 동일. [[dev-standards-pmo-tool]]
