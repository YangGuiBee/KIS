## 무엇인가
- **범용 웹 크롤링 에이전트**. 클로드 코드/ChatGPT에 github 링크를 주고 "클론·세팅해줘"라고만 하면 설치(리드미를 AI가 읽고 자동 세팅). 이후 **수집할 URL + "무엇을 모을지" 설명**만 하면 끝. 도구 자체는 무료(단, 클로드/ChatGPT **유료 구독** 필요).
- 결과물: **엑셀 표**, 웹사이트 **첨부 PDF 다운로드**, 비목록형 사이트는 **원문 MD** 저장까지.

## 동작 원리 (핵심 설계)
- **에이전트용 브라우저**로 대상 사이트를 **정찰** → 구조에 맞춰 **수집 전략 결정** → **LLM이 사이트별 수집 코드를 작성** → **코드(결정론적)로 정확히 수집**.
- **역할 분담**: "정확한 동작=코드 / 유연한 판단=LLM" — 사이트 구조가 바뀌어도 전략을 고쳐 대응. 수집 전략은 `fingerprint` 폴더에 저장해 재수집 시 더 빠르게.
- 기반 오픈소스 2개: **에이전트 브라우저**(정찰) + **Scrapling**(사이트별 수집). 저자가 수십 개 사이트 시행착오 노하우를 절차로 반영.

## 지원 사례
- 공공 입찰(나라장터), 금융감독원 보도자료(+첨부 PDF), 한국고전종합DB(비목록형→MD), 원티드 채용공고(상세 페이지 진입), 뉴스(조건 필터), 네이버 부동산 매물, 이커머스 리뷰(쿠팡·스마트스토어·11번가·컬리), 네이버 카페·인스타그램.
- **로그인 사이트**: 브라우저를 띄워 **사용자가 직접 로그인**(쿠키 상태만 인계, ID/PW 저장 안 함, 2단계 인증도 사람이 풀면 이어감).
- **봇 차단 사이트**(쿠팡 등): 정찰 단계에서 차단 감지 → "우회할까요?" **경고 후 사용자 승인 시** 진행(판단은 도구가 아니라 사용자).

## 커스텀 3가지 (맞춤형일수록 강력)
1. **자동 실행**: 루틴(클로드)·예약(ChatGPT)으로 매일/매시간 스케줄 크롤링·모니터링.
2. **결과 전달 방식**: 엑셀 → Slack 채널·이메일로 요약 전달(커넥터 추가).
3. **수집 항목 고정**: 특정 사이트·항목만 수집하도록 특화(예: 자사 리스크 PR 기사 모니터링→경고 알림).

## 법적 고려 6기준 (영상·리드미 정리)
①접근(약관·robots.txt 위반 여부) ②부담(서버 과부하) ③정보 성격(개인정보) ④분량(DB 상당부분) ⑤이용 목적(원본 대체·경쟁) ⑥흔적(밝히지 않고 몰래). 도구는 robots.txt 고지·요청 간격·개인정보 경고·우회 전 확인 등 **보조 수단**만 제공하고 **판단은 사용자 몫**. (저자는 변호사 아님 — 업무/상업 사용 전 전문가 상의 권고)

## 우리 업무 적용점
- 공공 입찰·규제(감독원) 동향 모니터링, 채용·시장·리뷰 데이터 수집 등에 바로 활용 가능. 수집→AI 분석(대시보드)까지.
- **무-지어내기·준법**: 실제 사용 전 robots.txt·약관·개인정보·저작권을 원 사이트 기준으로 확인, 내부 분석용 최소 수집 권장. [[no-fabrication-rule]] [[dev-standards-pmo-tool]]
