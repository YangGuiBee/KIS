## 핵심 내용
- 왜 일상감사인가: 서류·자격 검증, 법령·규정 검색, 검토서 초안 작성이 한 업무에 모두 들어 있고, 감사가 끝난 실제 사건의 문서·감사 의견이 있어 채점이 가능하며, 계약원가·업체 정보 때문에 폐쇄망이 필수. 기준은 「공공감사에 관한 법률」 제22조와 기관 일상감사 규정(중점 사항 8개, 실무 검토 7단계).
- 실험 설계: AI 감사직원 5종(세 축 독립 검토 / 역할 분담형 / 도구 호출형 / 단일 프롬프트 / 초안 후 재심사) × 로컬 LLM = 30조합 × 요청 4건. 받는 서류와 내는 의견서는 같고 일하는 방식만 다르게 했다. 폐쇄망에서 실행하고 외부 모델(Claude·GPT)은 채점 심판으로만 사용.
- 결과: 지침 4판 본실험 최고는 초안 후 재심사(Qwen 3.8 27B → 코드 검산 → gpt-oss-120b) 13/24, 지침 5판 재검증 최고는 단일 프롬프트 Qwen 3.6 27B(추론 켬) 16/24 → 1차 운영 후보. 단 "운영 인증이 아니라 개선 기준선"이라고 명시.
- 단계가 많다고 좋지 않음: 역할 분담형은 전체 비용 $3.62 중 $3.17을 쓰고 최고 7/24, 세 축 독립 검토는 4/24.
- 지침의 함정: 사람용 운영문서(약 3,300자)를 통째로 넣으면 직접경비 핵심 기준 적중률이 31.9%→8.3%로 하락. 요청 A용 '지적 강제형' 지침을 요청 B에 쓰면 과잉지적 억제 달성이 51.0%→14.3%로 하락 → 지침을 고칠 때마다 4건 전부 재실행·재채점.
- 초기 실패 3회: 입력 한도 초과(Qwen3 14B 16,384토큰), 정해진 출력 형식 실패·시간 초과(27B), 18개 모델 중 4개 무응답·실행 편차. 모델 규모를 키우는 것만으로는 해결되지 않음.
- 산출물: 실행 절차를 고정한 도구(하네스)와 사용자 화면(GUI)으로 배포, 실패 신호를 5개 유형으로 분류.

## 시사점
- 공공기관이 폐쇄망 로컬 LLM을 도입할 때 '어느 모델이 최고인가'보다 '같은 조건에서 공정하게 비교하는 방법'을 먼저 세워야 한다는 실증 사례. 실제 완료 사건을 정답지로 쓰는 평가 설계가 재사용 가능하다.
- 멀티 에이전트·호출 단계를 늘리는 것이 품질로 이어지지 않았고, 지침 변경이 다른 사건의 성능을 떨어뜨리는 회귀가 확인됨 — 지침 수정 시 전 사건 재검증을 표준 절차로 둘 필요.
- 외부 클라우드 모델은 채점에만 쓰고 실행은 폐쇄망에서 하는 구조는 보안 규정과 평가 품질을 함께 잡는 실무 패턴으로 참고할 만하다(AI기본법 고영향 판단·영향평가와 AIG 강의의 시험·평가 표준 연계 사례).
