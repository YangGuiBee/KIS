## 핵심 키포인트
- **설치·동기화**: 설치·로그인 후 기존 브라우저(크롬·엣지·웨일·사파리)의 즐겨찾기·북마크를 가져온다. 기본 검색엔진은 선택(강사는 퍼플렉시티 구독 해지 후 구글로 변경).
- **에이전트 설정이 절반**: ①알림 켜기 — 여러 창을 동시에 돌릴 때 완료 알림으로 확인 ②권한 — 강사는 전체 승인(풀 액세스, 스스로 읽기·쓰기)이지만 보안상으로는 '가드' 모드가 권장된다고 언급 ③작업 중 지시 변경 방식(즉시 끼어들기 vs 끝난 뒤 후속 지시) 선택 ④작업 폴더 지정 — 클로드·코덱스처럼 폴더 안에서 명령 실행.
- **가장 중요: 모델 설정**: GPT·Claude 계정을 클릭·로그인만으로 연동(API 키 불필요). 그 뒤 **태스크 기본 모델을 Aside 자체 모델로 두면 Aside 크레딧이 다 소진된다**(강사 실제 경험) — 반드시 내가 연결한 계정의 모델로 바꿀 것. 강사는 대부분 Claude Opus 5.5, 이미지·스크린샷 같은 시각 작업은 GPT로 설정.
- **스킬·MCP·메모리**: 스킬 = Aside 사용 중 생긴 업무 레시피 매뉴얼(Aside 폴더에 저장, 작업 시 참조), MCP = 외부 도구(손발), 메모리 = 사용 기록이 시키지 않아도 자동 정리되는 폴더.
- **비밀번호**: 기존 브라우저에서 비밀번호를 CSV로 내보내 Aside에 임포트하고 비밀번호 매니저 기본 사용을 켜야 로그인이 필요한 사이트 작업이 막히지 않는다.
- **루틴 = 자동화**: "매일 몇 시에 ~ 루틴 만들어 줘"라고 말로 시키면 Aside가 정해진 시간 작업을 등록. 단, **컴퓨터가 켜져 있어야만 돈다**.
- **하이라이트 — 클로드 코드/코덱스 연결**: 설정 > Developers의 Aside CLI 명령을 복사해 클로드 코드에 붙여 넣고 "설치·연결해 줘"라고 하면 끝. 클로드가 대충 말한 요청을 정리해 Aside에 넘기고 결과를 받아 보고하는 '중간 지휘자' 역할. CLI(명령으로 작업 요청)·MCP(도구로 제공) 둘 다 연결해 두면 상황에 맞게 골라 쓴다. 강사는 이 구조로 뉴스레터·카드뉴스 자동화를 시연.
- **킥(별표 50개): 맥락과 실행 분리** — Aside는 실행 도구. 작업 방식과 결과를 스킬로만 남기지 말고 과정까지 매뉴얼로 남기면, 그게 모여 위키가 된다.

## 우리 업무 적용점
- **가이아 지휘 구조와 같은 결**: 클로드 코드를 지휘자로, Aside를 브라우저 실행 손발로 두는 방식. 로그인된 내 브라우저를 대신 쓰는 장점이 있지만, 앞서 KIS 이벤트 파이프라인 검토 때 메일·카톡 수집에는 Aside 비권장으로 정리한 바 있음 — 쓸 경우 권한은 '가드' 모드로.
- **크레딧 함정 체크리스트**: AI 도구 도입 시 "기본 모델이 도구 자체 유료 크레딧인지"를 먼저 확인할 것(강의·사내 교육 시 주의사항으로 활용).
- **맥락/실행 분리 = KIS·Obsidian vault 전략**: 실행 결과를 매뉴얼→위키로 쌓으라는 조언은 코드저장소와 vault를 분리한 우리 방식과 동일. [[no-fabrication-rule]]
